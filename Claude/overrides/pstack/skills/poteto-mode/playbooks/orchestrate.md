### Orchestrate

Read ../../../docs/harness/claude-code.md. Coordinate a standing program with independently owned units; one task driven to a completion condition belongs in Autonomous run. The coordinator assigns work and verifies outputs. Branch owners implement code. Use the native Agent tool and substantive SendMessage continuations only when authorized; do not require Cursor Task/cloud arguments, the removed orch CLI, or a proprietary Project store.

Keep a durable tracker at an agreed project-owned path recording goals, units, dependencies, owners, branch/PR links, exact heads, evidence, verdicts, and next actions. A tracker does not create background execution. Continuation after the session requires an explicitly requested supported scheduler.

Each worker receives a standalone brief: intent, allowed and prohibited paths/actions, dependencies and their actual reports, acceptance commands and expected evidence. Use owned worktrees for independent writes and bound concurrency to this machine's slots, CPU, and ports. Start with one representative unit before expanding. Add a sub-coordinator only for an area needing several workers, with no more than three levels. Fresh workers handle independent tasks; substantive follow-ups can reuse a worker. Completion notifications observe progress without restarting an idle agent. Prefer PR/CI subscriptions when the harness offers them; otherwise make bounded checks and keep unchanged monitoring quiet.

Give each PR one designated branch owner; the coordinator never authors its fixes. Dependent PR topology changes have one designated writer. The owner changes bases or targets only under the coordinator's instruction and user authority. Read actual diffs and artifacts, not only summaries. CI is evidence, not a verdict. Behavioral changes need proof beyond a typecheck. Each PR requires an independent verifier at its current head and the shipping playbook's separate gates. Claude aliases do not prove different-family verification; disclose that limitation. A new push requires current evidence and verdicts.

Return scope drift to its owner. Judge stalled work by actual outputs and PR activity. Retry by cause with a smaller brief or replacement worker; after two unsuccessful retries, replan. Reconcile late outputs against the current head, retaining unique findings through an appropriate worker. Account for every worker as completed, replaced, or absorbed into another unit. Bring the user only decisions and blockers needing their input. Landing follows the user's explicit merge authority and shipping gates.

Finish with progress against the goal, every PR's live state/head/verdict and evidence links, dropped work and reasons, and outstanding user decisions. If delegation is unavailable or unauthorized, state the limitation and proceed sequentially within scope; do not claim a program ran.
